## 双语文本与资源体积

两份资源使用相同的图像、动画和卡牌图像目录，分别重建文本、索引和五种字号的字形。旧压缩动画组没有重新烘焙；追加的 48 个静态 UI 图像也在两语包之间逐字节相同。

UI literal 目录共有 **935 条绑定**：其中 **620 条映射到原版本地化键**，另 **315 条为计算器控制、诊断或兼容界面自有英文/fallback 文案**。这两个数字只描述该 UI 绑定目录，不是游戏全部字符串的数量。原版模板数值由对应模型和运行状态绑定；这轮没有使用自动机器翻译替代原版文案。

| 简体中文 | 81,124,916 | 81.125 | 11,900 | 2,380 |

两份包均包含 45,785 个图像条目、1,695 个动画 clip、558 个卡牌条目、8,192 个字符串槽位和 1,236 个辅助条目；字符串槽位数不代表同等数量的独立游戏文本。字号为 8、10、12、16、20。实际字体覆盖审计未发现文本或运行时符号缺字；英文包字符串的 CJK 数量为零。该静态审计不单独证明每个动态运行路径都已翻译。

## 主机回归、视觉审阅与 WASM

Source35 的最终相关验证是 **18 项独立执行**：10 项 fallback 执行，以及中文、英文各 4 项实际资源执行。实际资源的四项为世界文本、世界 UI、关键词提示和计算器反馈回归。ASan 与 UBSan 启用；LeakSanitizer 因执行环境无法枚举任务而关闭，因此没有泄漏检查通过的声明。这里没有把历次断言数相加，也不把这 18 项称为所有游戏内容的完整测试套件。

视觉审阅共 **48 帧**：两语各 18 帧卡面/HUD/角色选择，共 36 帧；另有两语关键词、状态和回合提示共 12 帧。审阅发现并修复了第三行状态被 Detail 文字及点击区域覆盖的问题。最终图中 Detail 位于空闲侧边，负数及三位数层数仍可读；较长卡牌正文通过省略号和详情页处理。320×240 小卡的实际阅读舒适度仍需使用者在设备上判断。

Source35 Native 与 WASM 使用同一份三敌人存档、各自对应的最终语言包，完成准备阶段及之后 720 帧的观察。每种语言的五个 RGB565 检查点与分阶段读取次数/字节数一致，规范化存档状态保持不变，没有保存回调；WASM 线性内存固定为 16,777,216 字节。这证明这些采样点的跨目标一致性，不是原版引擎对照，也没有测量浏览器 RAF、浏览器合成开销或物理计算器 FPS。

## 性能：已经减少的工作与仍存在的等待

保留的 Source27/Source33 ABBA 对照使用完全相同的 v16 资源和三敌人存档，统计准备、首次可见画面及随后 720 帧。该范围读取量从 **24,097,642 字节降至 2,162,452 字节，减少约 91.026%**。Source35 对同一输入的单次复核保持相同 I/O 数量。该比例是资源读取量变化，不是运行速度提升比例。

Source35 对最终 v17 资源的相同观察范围分别读取中文 2,224,072 字节、英文 2,113,480 字节。准备需要 59 次更新、每次最多四张冷图；测试以每帧 33ms 推进逻辑时钟，因此 1,947ms 只是这套推进安排的准备等待下限，不是实测设备加载时间。

Firebird 使用报告为 396 MHz 的 CX II CAS 配置；它不是物理计算器或逐周期性能测量。完整性检查与动画索引验证仍占明显启动时间。现有记录没有证明冷启动提速，也不能把不同资源、不同进程或不同输入场景的时间直接相减作为 A/B 收益。

## 种子、退出与保留的失败

Source33 的普通 UI 流程中，A 新局显示种子 `E80C6A8B`，重新进入程序后 Continue 保持该显示值、内部 32 位种子和 64 位 run seed；随后 B 新局显示 `0651E28D`，三个字段均改变。没有手动种子、修改存档或写入模拟器 RAM 来制造这一结果。该流程的首份性能报告由不可变 snapshot 只读恢复，并与暂停时计数及序列化 NAND 内容对应；它不是 USB 导出的首轮报告。

同一流程暴露了退出问题：确认 Quit 时单次 ENTER 按住 80ms 后，出现了程序再次启动。Ndless r2022 本身也有释放检查，因此仅凭程序本地原先没有等待不能确定重开的机制；某个时刻的 PC 位于 OS 也可能只是系统调用。Source36 增加正常退出前连续释放 100ms 的检查、10ms 输入采样间隔和 2 秒总上限，使用既有前台计时器，不修改系统键盘队列。

**Source36 已通过相同 80ms ENTER 操作的退出复测。** 按住期间，`app.quit` 已为真，程序仍保留前台并显示游戏标题；松开后观察 5 个模拟秒，画面为 OS 文件浏览器，没有自动重开。此次没有缩短按压、改用其他确认键或强制终止游戏。这证明该复现输入的结果已改善，尚不能确定底层 Ndless/OS 事件机制，也不覆盖所有按键时序。

同一次最终运行从 B 存档 Continue 到涅奥房间，显示种子 `0651E28D`，内部两个种子字段与 Source33 B 一致。正常保存并经 USB 导出的 230,088 字节存档与 B 原文件逐字节相同，生产存档解码检查通过。正常 USB 导出的 4,393 字节性能报告与暂停时的启动、首次渲染和首次呈现计数精确对应，资源读取失败为零。该补测继承此前 OS/文件系统缓存状态，其 41.741 秒启动记录不能与前述 52.353 秒直接相减，作为冷启动提速证据。

失败与纠正记录保留，后续成功不会覆盖它们：

- Source31 首次 sanitizer 批次受到 LeakSanitizer 环境限制；后续仅关闭泄漏扫描，保留 ASan/UBSan。
- Source33 实际资源测试暴露了 fixture 问题：关键词用例未等待准备结束、直接进入战斗却保留 turn=0，以及把中文 Dusty Tome 的 `+` 写法强加给原版英文。修正测试前的失败仍保留；Source35 两语实际执行重新通过。
- Source34 实际画面发现密集状态与 Detail 的视觉/命中冲突，原先“有多少个 hit”并不能发现后者；Source35 改为检查有效 `hit_at`。
- 一次中文小图被误读为旧术语“星星”。原版键和实际文本缓冲区确认“辉星”，因此撤回该判断，没有为迎合误读而修改原文。
- Source35 首次 WASM 复用证明失败源于临时输出文件名改变了 WASM 自定义 name 段。之后使用相同 basename 完成完整文件哈希验证，没有放宽一致性检查。
- Source33 退出后的错误 USB 请求和预期截图标签均保留；没有把第二次启动画面计作正常返回 OS，也没有把未完成的 USB 请求计作成功导出。

## 最终验证与剩余工作

Source36 ARM 构建已通过：launcher 为 939,953 字节，Zehn 分配 16,311,912 字节，距 16 MiB 上限余 465,304 字节。仅重编 Ndless 的 `main.cpp`，其余 26 个对象在输入和哈希检查后复用。Source35 → Source36 的 Native/WASM 输入关系已逐项验证一致，因此保留 Source35 的实际执行记录；资源仍是 Source33 的两份最终包。

最终 launcher 的安装文件经 USB 回读与构建产物完全一致，中文 Firebird 验证 journal 已以 `passed` 结束，冻结源码在执行期间没有变化。Source36 的最终执行范围为启动、标题、Continue 到已保存的涅奥房间、保存、上述退出复现和正常导出。Source35 的主机/WASM 证据与 Source33 的较广中文游戏流程证据保留各自 checkpoint，不自动改名为 Source36 执行结果；本轮没有英文 Firebird 执行。

后续仍应优先处理可读性和原版 UI 的剩余差异，并继续测量冷启动、战斗准备和真实设备上的帧间隔。所有原版敌人/能力的全动画、每个关键词、全部材质/VFX、原版房间图标/计时及完整角色动画背景，不因本轮部分场景通过而视为完成。
