# Original map presentation — 0.17

Reference: the owner's pinned **v0.111.0 / 41cef1ea** installation. This document records implemented source, the evidence used for its coordinates and assets, and remaining visual differences. It does not assert a measured 95% similarity result.

## Source contracts

The private reference types are `NMapScreen`, `NMapPoint`, `NNormalMapPoint`, `NAncientMapPoint`, `NBossMapPoint`, `NMapMarker`, `NMapCircleVfx`, and the four act models. Their corresponding public resource paths, dimensions and selected animation metadata are recorded in `config/world-map-ui-0.17.json`. Original scene files, decompiled text, textures and derived packs remain private.

The reviewed scenes are:

- `scenes/screens/map/map_screen.tscn`
- `scenes/ui/normal_map_point.tscn`
- `scenes/ui/ancient_map_point.tscn`
- `scenes/ui/boss_map_point.tscn`
- `scenes/ui/map_dot.tscn`
- `scenes/vfx/map_circle_vfx.tscn`

`NMapScreen.SetMap` uses seven columns, 150 logical units between columns and `2325 / (rowCount - 1)` between rows. A map with a second Boss applies the original 0.9 row-distance factor. Normal controls start at `(column * 150 - 500, row * -distance + 740)` and have a `(28, 28)` center offset. Ancient and Boss controls have their own authored anchors and pivots; the second Boss scales both Boss controls around their original pivots.

The layout helper reproduces the named `map_jitter_<act>` stream from a local RNG copy and the original column-major grid enumeration. Each normal point consumes the two original position draws, within ±21 and ±25 logical units. Its arithmetic rounds at the original binary32 boundaries using the existing software floating-point bridge, so freestanding ARM needs no new floating-point runtime or math library. Rendering, repeated layout queries, selection and scrolling do not advance any saved RNG stream.

## Drawn map

`include/world_map_layout.hpp` calculates positions and scroll bounds without changing `State`. `src/world_map_ui.inc` draws the actual saved map graph, and `src/world_map_draw.inc` supplies bounded, clipped original-image drawing, tinting and the Boss RGB-mask conversion. `src/world_map_input.inc` implements map-specific navigation and its folded legend.

The renderer uses the three authored background layers for each of Overgrowth, Underdocks, Hive and Glory. It retains each region's original map paper, visited and unvisited colors. Real graph edges become dotted paths; only traversed edges receive the visited style. Normal visited points use the original completed circle image. Unknown points reveal the room initially entered at that map coordinate. Ancients use their model-specific icon and outline, and Bosses use their own icon or animated mask, rather than a generic combat glyph. Spoils marks the first Treasure node in the original grid order when that card applies to the current act.

The new manifest contains **60 images**. Existing normal node images and five character markers are reused. The appended images comprise 12 background layers, six normal outlines, four revealed-unknown icons, 16 Ancient icon/outline images, 18 static Boss icon/outline images, and the circle, dot, legend and quest images.

Three Bosses use the original full map animation cycles:

| Boss | Clip | Original duration used by UI | Frames |
| --- | --- | ---: | ---: |
| Ceremonial Beast | `animation` | 6,000 ms | 120 |
| Queen | `animation` | 10,300 ms | 206 |
| The Insatiable | `animation` | 10,667 ms | 214 |

The 540 frames keep a fixed 100 × 100 canvas and the original scene pivot. The resource converter samples the entire source cycle; the UI selects frames using elapsed time divided by the actual cycle duration. In particular, it does not accumulate the Insatiable's 33 ms discrepancy from treating all 214 frames as exactly 50 ms. The original red/paper, blue/ink and green/white channel combination is applied during drawing. The nine remaining Boss models use their actual static images and source aspect ratios.

## First-room history and save data

`WorldState::visited_rooms[3][143]` records the first room type on entry to each visited point. It is set alongside the visit flag after resolving an Unknown room. Entering combat inside an event does not replace this value, and the Architect's room at the final Boss coordinate does not rewrite the Boss visit. A map regenerated by an Ancient modifier resets both arrays and restores the Ancient's visit consistently.

The 429 bytes are appended to the unpublished v15 codec suffix. Historical v3–v14 layouts are unchanged. The validator requires a room type for every visited point, rejects history on unvisited points, checks fixed node types and limits Unknown results to their permitted room categories. The original map point remains `Unknown`; revealing its UI icon never edits graph topology or future room selection.

Core regression source covers the Ancient visit, a real route to an Unknown that resolves to combat, unchanged graph type, impossible history rejection, nested event combat and byte-exact save/load. The existing native run and historical expedition retain separate entry and routing paths.

## Calculator adaptations and interaction

The original logical map geometry is uniformly scaled by 0.22. The viewport occupies rows 44–204 of the 320 × 240 screen, leaving legible space for the header and action footer. Background layers fill the available width. Vertical scrolling is bounded by the actual active graph, including both A10 Bosses. Opening the map during a room or combat is inspection only.

Left and Right cycle through the actual reachable frontier. They do not select empty columns. Up and Down scroll by one scaled row. Confirm while scrolled away first returns to the frontier; a subsequent confirmation enters the selected reachable room. Normal node touch regions are 30 pixels wide, Ancient regions 48 pixels, and Boss regions follow their larger visible controls, with all hits clipped to the viewport.

The legend folds into an explicit button/Detail-key action to fit the calculator display. Its six original room categories retain their original icons and highlight matching nodes. While open it replaces node interaction, and its state participates in the pointer input context so a press begun on a node cannot enter a room after the modal changes. The selected-node footer and character marker are enlarged for readability; the marker is 16 pixels instead of the roughly nine pixels obtained from an unadjusted uniform scale.

The map's legend, selection, scroll and marker state belong to `App`, not the saved game. Presentation reset also clears the offered-card growth detail cache. Regression source checks complete serialized state equality around map inspection, repeated rendering, legend actions and scrolling.

## Known visual gaps and verification boundary

The source preserves the original named position jitter. Original rotation and dot noise use the process-global `Rng.Chaotic`, whose prior process history is not in a run save; the calculator instead uses stable local cosmetic noise. This difference is documented rather than described as original seeded reproduction.

Visited circles currently show the original completed frame. The five-frame entry animation, original map-entry tweens and the marker's short entry motion are not implemented. Selection uses a small drawn corner reticle rather than the original reticle texture. The dot and node angle distribution is an approximation of the original cosmetic Gaussian noise. These are fidelity gaps, separate from required font, viewport and touch-target adaptations.

The implementation has passed short C++ syntax checks. `tests/world_map_ui_regression.cpp` is source-ready: its default mode uses a synthetic resource profile for input/serialization assertions; optional actual-pack and output-directory arguments capture the four regions, all 12 Boss model views, the A10 second Boss, current combat inspection and the legend. This new suite has not yet run from a frozen, remotely verified checkpoint, and the new map UI has not yet been visually compared with the actual private pack or an unmodified-game capture. Full native, cross-target and visual results must be recorded separately after that checkpoint; resource declarations and syntax success are not visual acceptance.
