# Conversion cache identity and resource checks

The current user policy removes integrity checks that are not original-game
requirements or functional prerequisites. This also applies to the private
resource conversion tools. Conversion cache keys remain useful: changing a
renderer, source skeleton, material, sampler runtime or requested job must not
silently reuse pixels generated by a different input.

The world converters now use the actual supplied Spine runtime and FastNoise
header in their compiled-adapter and pixel-cache identities. They do not
require those files, or the old retained pack, to match a hard-coded SHA.
Original scene/animation/material selection and actual parser dimensions and
bounds remain in place. Runtime identity fields in conversion metadata report
the supplied sampler; they no longer report an assumed fixed binary.

Cached payloads are read once and checked against their declared byte count.
Frame consumers still parse the required frame count, dimensions and ranges.
An unused old payload digest does not reject a record, and newly written cache
receipts no longer compute that redundant digest. The dependency/settings
hash chooses the record; it is not an extra verification pass over its pixels.

Rest prefetch workers share a per-job lock and atomically publish completed
records. The former repeated whole-source scans, post-publication payload
readbacks and final all-record signature scan have been removed. The source
identity is captured once for the functional renderer cache key. Existing
checkpointed execution supplies the reproducible build boundary; prefetch
does not repeatedly re-audit the running source tree.

Synthetic tests retain coverage of cache selection across renderers/runtimes,
missing/truncated records, job and frame compatibility, shared worker reuse and
atomic publication. Integrity-only digest mutation and unrelated concurrent
writer detection are no longer required behaviors.
